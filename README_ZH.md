## 为什么做这个

邮箱是这个世界上通用性最好的开放消息系统 —— 谁都有，而且**对方不需要装任何东西**
就能收到你的消息。这一点是任何即时通讯软件都做不到的。

但邮件客户端一直把它当成**公文**来处理：主题、称呼、正文、落款、引用历史、
「尊敬的 XXX」。一件两小时内来回四条的小事，最后长得像一叠待办文件。

clichat 换个看法：**把邮件当消息。**

- **按会话读，不按邮件读。** 回复关系直接用邮件本来就带的 `References` /
  `In-Reply-To` 头部聚合，不做主题猜测 —— 把「同标题的两场不同讨论」错误合并，
  比留下断链更糟。
- **一个二进制，没有服务端。** IMAP 和 SMTP 从你的机器直连你的邮箱服务商。
  没有 clichat 账号，没有中转服务器，中间不经过任何第三方。
- **凭据只属于你。** 授权码用你自己设的主密码加密后存在本地，除了你自己的
  邮件服务器，不会被发往任何地方。
- **不发明任何自定义邮件格式。** v1 在协议层没有加任何私货 —— 所以它发出去的
  每一封信，在任何别的客户端里都读得懂；别人从别处发来的信，在 clichat 里
  也能正确成会话。

## 快速开始

```bash
clichat
```

首次启动会走一个四步向导：

1. **选服务商** —— QQ 邮箱 / 163 / 126 / Gmail，或「自定义」（自己填服务器）
2. **邮箱地址**
3. **授权码** —— ⚠️ **不是登录密码**。几乎所有服务商都要求用应用专用密码或授权码
   才能走 IMAP/SMTP，向导里会告诉你所选服务商的授权码去哪拿。
4. **主密码** —— 至少 4 位。它用来加密授权码，永远不会被发送到任何地方。

之后**每次启动都要输这个主密码**。忘了就只能重新配置账号 —— 在主密码界面按
`Ctrl+R` 可以重来。

### 命令行开关

| 开关 | 作用 |
|---|---|
| `-check` | 只读连接自检：连一次邮箱，报出断在哪一步。用的是已保存的配置，除了主密码不会再问你任何东西。 |
| `-check-deep` | 同上，外加实测一次首拉耗时。明显更慢，隐含 `-check`。 |
| `-version` | 打印版本号后退出。这个版本号同时也是发给服务端的 IMAP `ID`。 |
| `-config-dir` | 打印配置目录后退出。 |

脚本里用环境变量 `CLICHAT_MASTER` 传主密码 —— `-check` 会优先读它，读不到才回退到
交互式输入。**刻意没有「密码」这个命令行开关**：命令行参数会进 shell 历史，也会出现
在进程列表里。

## 功能

**读**

- 按 `References` / `In-Reply-To` 聚合会话，不靠主题猜测
- 自动识别群聊；每个发言人一个**稳定**的颜色，同一个人在每次启动后都是同一个色
- HTML 邮件转成 Markdown：链接和按钮都还原成可点的地址，表格、列表、代码块尽量留住原来的样子，标题按**字号**反推层级、粗体按 `font-weight` 认出来（真实邮件用行内样式而不是 `<h1>` / `<b>`）；引用历史砍掉 —— 聊天视图里引用是冗余的。具体怎么转的见 [HTML 邮件怎么变成 Markdown](#html-邮件怎么变成-markdown)
- 而且这层 Markdown 会被**渲染回终端样式** —— 标题的井号消失、不同层级的标题用不同颜色区分、列表补上真实序号、表格变成对齐的列、图片显示它的 `alt`、链接依旧可点。你读到的是邮件，不是标记
- 两栏布局，宽度低于 80 列自动降级成单栏

**写**

- 写新会话、回复、回复所有人（`Tab` 切换）、转发
- 星标（`*`）、标记未读（`u`）、删除（`d`）
- 删除是移到服务端的**已删除**文件夹，可恢复，而且会先弹确认框
- 复制最后一条消息正文到系统剪贴板（`y`）
- 搜索参与者、主题、显示名，边打字边过滤
- 切换文件夹（列表里按 `Tab`）—— 文件夹列表来自服务端 IMAP `LIST`，
  所以不管你用哪家邮箱、它把文件夹叫什么，都能对上

**让它一直能用**

- 冷启动只拉最近 90 天 / 500 封（先到者为准）
- 「接收全部邮件」模式（列表里按 `a`）：把本地游标退回去，历史邮件一次拉完。
  开着的时候状态栏会一直标着 —— 开了它首次同步会明显变慢，这事得看得见
- 按 UID 增量同步；断线重连从上次的 UID 续上
- 检测到 `UIDVALIDITY` 变化就重建本地索引
- 单封邮件解析失败只跳过那一封并记日志，不崩
- 只要服务商 IMAP 声明了 `ID` 扩展就能用（见「常见问题」）

**实现上**

- 纯 Go，`CGO_ENABLED=0`，每个平台一个静态二进制
- 凭据加密用 Argon2id + NaCl secretbox
- 本地索引就是 JSON，没有数据库
- 落盘的东西全在一个目录里，删掉即重置

## HTML 邮件怎么变成 Markdown

你真正在意的邮件大多是 HTML —— 而那个 HTML 不是文档，是**版式**。「确认订阅」
按钮是一个套了一堆行内样式的 `<a>`：把标签抹掉，字留下了，地址没了，而地址才是
唯一有用的部分。营销邮件的*整个正文*常常就是一个带内边距的 `<table>`。这两样都
不是正则能处理的。

所以 clichat 把 HTML 解析成 DOM（`golang.org/x/net/html`）再遍历，输出 Markdown。
它遵循的约定：

- **链接和「按钮」统一变成 `[文字](链接)`。** 邮件里的按钮要么是套了样式的
  `<a>`，要么是 `<button>` / `<input type=submit>`。只有前者带 `href`，所以两者
  共用同一条兜底链：`href`、`formaction`、`data-href`、`data-url`、`data-link`，
  最后连 `onclick` 里的 URL 也挖。挖到就是链接；挖不到就把文字加粗 —— 没有目标
  地址的按钮本来也变不成链接，但也不该混在正文里看不出来。
- **图片按钮取它的 `alt`。** `<a><img alt="查看订单"></a>` 是很多通知类邮件的按钮
  写法。终端显示不了图，而 `alt` 正是为「显示不了」而写的文字。
- **裸露的 `<img>` 变成 `![alt](src)`。** 同一个道理，只是外面没有链接：终端能
  显示的只有那个 `alt`。`alt` 和 `title` 都空着时，用一个占位词，**不留空标签** ——
  空标签仍然会把 `src` 留在屏幕上，而那个 `src` 通常是带了你标识的追踪地址。
- **标记包在内容外面，不包元素。** `**你好 **` 的尾随空格会把标记顶开、加粗当场
  失效，所以 `<b>你好 </b>世界` 必须转成 `**你好** 世界`，把空格挪到标记之外。
- **判断一个 `<table>` 是数据还是版式。** 首行有表头单元格、或者各行数列数一致，
  就是数据，转成 Markdown 表格；否则是版式，单元格按块**竖着摞**。把版式表拍平成
  一行，整封邮件会挤成一坨。
- **标题从字号反推，而不是只认 `<h1>`-`<h6>`。** 真实邮件里几乎没有标题标签 ——
  邮件客户端会把标题标签自带的样式 strip 掉，所以发件人宁可把字号直接写进
  `<td style="font-size:28px;font-weight:bold">`。只认标签的话，整封信的层级会在
  转换时全塌：大标题、小节标题、正文变成一串同样大小的段落，分不出谁是谁。做法是
  先估出这封信的**正文字号**（每段文字按**字数**加权投票，只算最内层的声明，
  并列取小），再把明显更大的字号按倍数分档成 `#`~`######`。判据刻意收紧：元素得
  自己声明 `font-size`（继承的不算）、内容里不能有块级子元素、链接、按钮或图片 ——
  按钮常长得最像标题（大字号、加粗、白字），只有「里面是个 `<a>`」能把它们分开。
- **粗体也认样式，不只认 `<b>`。** 同一个原因：模板把 `font-weight:bold` 写进
  `style`，只认标签的话正文里的强调全平了。`bold` / `bolder` / `600`-`900` 都算，
  老模板的 `<font weight="bold">` 也算。
- **标记不许嵌套出渲染器认不出的串。** 样式加粗和标签加粗叠在一起会写出
  `**甲**乙****`，`<b><i>甲</i></b>` 会写出 `***甲***` —— 渲染端刻意拒绝有歧义的
  星号串（宁可整段原样显示），所以生成端就得压平：已经在星号里时内层不再加标记。
  `~~` 不在此列，它和星号不冲突，`**甲~~旧~~**` 渲染得出。
- **正文里的特殊字符转义。** 正文写着 `2*3` 或 `[限时]`，不该变成斜体，也不该
  凭空多出一个链接。
- **引用历史砍掉。** 聊天视图里把刚读过的会话再引一遍是噪声 —— 会话本身就在那儿。

它不还原 CSS。终端里没有「左边距 40px」这回事。

### 而这层 Markdown 还要渲染出来

只转成 Markdown 是做了一半。终端里把 `**注意**` 原样显示成 `**注意**`，
只是把问题挪了个地方 —— 直到前不久这里就正是这样。现在聊天视图会把正文
渲染回能读的样子：`###` 变成一行粗体、列表项补上真实序号（`1.` `2.` `3.`，
而不是三个 `1.` —— 生成器刻意给每一项都写 `1.`）、`[文字](链接)` 只留文字
但仍然可点、进去时被转义的 `2*3` 还原成 `2*3`。

**标题还要分得出层级。** 终端里没有字号，能用的维度只剩**颜色**和**加粗**。
六档必然有几档长得一模一样，等于骗人 —— 所以按结构作用折成三档：

| 级别 | 画面 | 理由 |
| --- | --- | --- |
| `#` `##` | 强调色 + 加粗 | 这封信在讲什么 |
| `###` `####` | 另一种颜色 + 加粗 | 这一节在讲什么 |
| `#####` `######` | 只加粗 | 邮件里基本不出现，不再叠颜色 |

只有解析层知道「哪些级别算大标题」，渲染层只负责把它翻成样式 —— 分档规则是
Markdown 的语义，不是终端的事。属性位里用最高两位存这个「显眼程度」，它是
`attrs` 里唯一一个**多位存值**的属性（别的都是有/无，标题层级天然是个值）。

这里没有用 Markdown 库。输入语法是**封闭**的一套，因为这套 Markdown 本来就是
clichat 自己写的：正文里来的每个 `*`、反引号、`_`、`[`、`]`、`<` 出去时都被
转义成了 `\<字符>`。所以**没被转义的 `*` 一定是自己写的标记**，解析可以做到
确定；通用渲染器则不得不去猜。

**「封闭」是个承诺，翻车就翻在这条上。** 生成端早就在写 `![alt](src)` 和 Markdown
表格，渲染端两样都不认。它们不报错，只是把标记原样铺出来：`![Operational](…)`
显示成 `!perational`（`!` 留下了，图没有），状态表格显示成三行 `| 组件 | 状态 |`,
`![](url)` 则把一整条追踪地址塞进了会话中间。

教训已经写进测试里了。渲染器的判据末尾有一条**跨包不变量**：真 HTML 走一遍
**真实的**生成器，再走一遍**真实的**渲染器，两头都钉 —— 屏幕上不许有标记，
文字也不许少。这次之所以能漏过去，正是因为两边各自测自己；两个包都是绿的，
而它们之间那道缝是空的。生成端以后每学会一种语法，该由这条判据告诉你渲染端
还没跟上。

两个决定「看着顺不顺眼」的细节：

- **折行在纯文本阶段完成，上色在折行之后。** 一段颜色转义序列就是一串字符，
  而按 rune 算宽度的东西会把它当成列数算进去 —— 先上色再折行，折点会落错位置，
  还会把转义序列拦腰切断。颜色最后上。
- **链接只上前景色，别的属性一律不加。** 给链接的样式加下划线，渲染器就会
  **逐字符**输出一串转义序列，把「可点击链接」那段序列冲散：链接看着完全正常，
  但点不动。宁可要一个能点的链接，也不要一个带装饰的。

表格还多一条规矩：**不折行。** 一行表格折开了，列就对不齐，那还不如它替掉的那段
纯文本。所以超宽的表格按**列**逐步收回 —— 状态词这种窄列不会被宽列连累 —— 只有
窄到实在放不下时，才彻底放弃对齐，把单元格按普通正文折行铺开。

## 常见问题

**哪些邮箱开箱即用？**

QQ 邮箱、163、126、Gmail 都有预设 —— 自动填好服务器和端口，并告诉你授权码去哪拿。
其它的用「自定义」手填即可。

**为什么预设里没有 Outlook / Outlook.com 个人版？**

微软从 2024-09-16 起停用了个人版账号的 IMAP/SMTP 基本认证。填密码连不上，
必须走 OAuth2，而 v1 不做 OAuth2。**这是刻意不给，不是忘了。**
iCloud 同理排除 —— 它的服务器地址没有核实过，给一个可能错的预设比不给更糟。

**163 / 126 报 `Unsafe Login. Please contact kefu@188.com`**

网易系要求客户端登录后先发一条 IMAP `ID` 命令表明身份（RFC 2971），
否则后续命令一律被拒。这个错很坑：**`LOGIN` 是成功的**，挂在紧接着的 `EXAMINE` 上。
clichat 从 v0.1.0-beta.9 起会发这条 ID。如果你用的是更早的版本，升级即可。

**连不上，怎么知道断在哪一步？**

```bash
clichat -check
```

它会用你已经保存的配置连一次邮箱，然后按步骤报结果：① 登录并选中 INBOX、
② 拉一段邮件头部、③ 探测「已发送」文件夹。**停在哪一步，就说明问题在哪一层** ——
是授权码不对，还是服务商限流，还是端口到不了。

自检是**只读**的：不读正文、不打印主题和发件人、也不会把邮件标成已读。所以它的输出
可以直接贴到 issue 里。

加 `-check-deep` 会额外实测一次首拉耗时。首拉几百条头部要几十秒，而那段时间界面上
只显示「同步中…」，很容易被误当成卡死 —— 这个数就是用来判断「慢」还是「真挂了」。

**每次都要输主密码，能不能记住？**

v1 不能。存到系统钥匙串在路线图上。

**我的数据存在哪？**

| 平台 | 目录 |
|---|---|
| Windows | `%AppData%\clichat` |
| macOS | `~/Library/Application Support/clichat` |
| Linux | `~/.config/clichat` |

| 文件 | 内容 | 是否加密 |
|---|---|---|
| `config.json` | 账号、服务器、同步策略 | 否 |
| `credentials.enc` | 授权码 | **是**，主密码加密 |
| `index.json` | 邮件头索引 | 否 |
| `clichat.log` | 运行日志 —— 只记事件，不记正文 | 否 |

整个目录删掉就是彻底重置。

**搜索搜不到很早以前的邮件。**

搜索只覆盖**本地已同步**的部分 —— 默认最近 90 天或 500 封，不会去查服务端。
需要更多的话，调 `config.json` 里的 `sync.initial_days` / `sync.initial_max_messages`；
或者在会话列表里按一下 `a` 打开「接收全部邮件」，把服务器上的历史整份拉下来。
拉完之后这些邮件同样能被搜索到。

**按 `d` 是真的把邮件删了吗？**

不是。它把邮件**移到服务端的「已删除」文件夹**，你还能从网页版找回来。
服务端支持 IMAP `MOVE` 扩展时用它；否则退化成 `COPY` + 打 `\Deleted` + `EXPUNGE`。

**支持附件吗？**

v1 不支持。解析时会忽略附件，只显示文本部分。

**支持多账号吗？**

v1 不支持。

**出问题了，怎么拿到细节？**

日志在上面那个目录里的 `clichat.log`。如果是连接层的问题，启动前设
`CLICHAT_IMAP_DEBUG=1`，完整的 IMAP 协议对话会写进同一个文件 ——
**其中包含邮件头部和正文**，排查完记得关掉。

## 开发

需要 Go 1.26.2 或更新。

```bash
git clone git@github.com:PleaseEnterYourText-Studio/clichat.git
cd clichat

go vet ./...
go test -race ./...
go build -o clichat .
```

分层（依赖方向自上而下）：

| 包 | 职责 |
|---|---|
| `internal/thread` | 纯函数聚合算法（并查集）。无 IO，可完全单测 |
| `internal/mail` | IMAP 拉取 / SMTP 发送 / MIME 解析，藏在 `Client` 接口后面 |
| `internal/store` | 邮件头索引，JSON 持久化 |
| `internal/config` | 配置、服务商预设、Argon2id + secretbox 凭据加密 |
| `internal/logging` | 运行日志 |
| `internal/app` | 编排层，把上面几块拼起来 |
| `internal/tui` | Bubble Tea 界面 |

自动化测试**永远不碰真实邮箱**，`mail.Fake` 提供内存实现。
`internal/tui/screenshot_test.go` 负责重新生成本文里的截图，用法见该文件顶部的注释。
